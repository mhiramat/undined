# UndineD Development & Coding Guidelines

Guidelines and invariants for agentic development on the Undine Linux kernel mail workstation.

## 1. Privacy, Anonymity, and Path Portability
- **Anonymization in Code and Tests**: Never use the developer's real name (Masami Hiramatsu) or personal email (`mhiramat@kernel.org`) in sample data, tests, mock emails, or documentation. Always use neutral placeholders such as `"Kernel Developer"` and `"dev@example.com"` (or `"dev@kernel.org"` for mock lore emails).
- **No Absolute Paths**: Avoid exposing machine-specific absolute filesystem paths (e.g., `/home/...`). Use relative paths (e.g., `./bin/undined`) or configuration variables for storage and binary paths.

## 2. Build and Test Invariants
- **FTS5 Build Tag**: Undine relies on SQLite FTS5 for full-text search. All test and build invocations must include the `fts5` tag:
  - `make test` or `GOTOOLCHAIN=local go test -tags "fts5" ./...`
  - `make test-e2e` or `GOTOOLCHAIN=local go test -tags "fts5" ./test/e2e/...`
  - `make build` or `GOTOOLCHAIN=local go build -tags "fts5" -o bin/undined ./cmd/undined`
- **Go 1.26 Compatibility**: Maintain Go 1.26 language and toolchain compatibility. Always prefix Go invocations with `GOTOOLCHAIN=local` to prevent unexpected automatic toolchain upgrades in `go.mod`.
- **Pre-Commit E2E Testing Requirement**: Always run the End-to-End test suite (`make test-e2e`) and full test suite (`make test`) before making any git commit to verify that no end-to-end user workflows or daemon processes are broken.

## 3. Git Commit Hygiene
- **Run E2E Tests Before Committing**: Run `make test-e2e` and ensure all tests pass prior to committing any changes.
- **Pre-Commit Go Review Subagent**: Before committing changes that affect Go source files (`*.go`), invoke a subagent with the `go-review-agent` skill to review the uncommitted changes (`git diff`). Address all identified findings before proceeding with the commit.
- **Update `AGENTS.md` on User-Requested Changes**: Whenever modifications or updates are made in response to user requests, update `AGENTS.md` to document the new invariants, behaviors, or architectural rules as you commit them to the repository.
- **Separate Commits**: When addressing multiple distinct bugs, vulnerabilities, or enhancements, commit each logical change separately with an explanatory commit message. Avoid bundling unrelated changes into a single commit.
- **`Fixes:` Trailer on Bugfix Commits**: Whenever fixing a bug or regression introduced by an earlier commit, identify the offending commit with `git log` / `git blame` and include a Linux kernel-style `Fixes: <12-char-hash> ("<subject>")` trailer at the end of the commit message to clarify the origin of the issue.
- **Message Wrapping & English Explanation**: Commit messages must be written in English, wrapped before the 80-character mark (recommend 72 characters for body text and 50–72 characters for subjects), and include at least 3–4 lines of body explanation describing the motivation and key changes, except for `Fixes:` trailers which must remain on a single unwrapped line.

## 4. Process and Command Safety
- **Input Sanitization**: Strictly sanitize user-controlled parameters (Message-IDs, Git refs, target coordinates) before passing them to subprocesses or queries.
- **Configurable Tool Execution**: For external review agents or runners, allow user-configured wrapper scripts rather than hardcoding raw CLI commands.

## 5. Patch Integrity & Non-ASCII Handling Policy
- **No Silent Normalization**: Never silently convert or sanitize non-ASCII characters (e.g., `\u00a0` NBSP, `\u2002` en-space) in patch diffs into ASCII whitespace.
- **Mark as Corrupted**: Treat any email with non-ASCII characters in its diff lines as corrupted (`is_corrupted = true`).
- **Reject SideDiff**: Do not render corrupted patches in the SideDiff dual-column view. Display them as plain text with non-ASCII characters visually escaped (e.g. `<U+00A0>`) and warn the user.
- **Reference**: See `docs/POLICY_PATCH_INTEGRITY.md` for full background, security rationale, and presentation rules.

## 6. Reply Quoting, Body Retention & Editor Invariants
- **Full Quoting on Zero Comments**: When composing a reply or generating review quotes without inline comments, always quote the entire body of the original email with standard RFC `> ` quoting prefixes. Never emit an empty or truncated quote.
- **75-Column Auto-Wrapping for Review Comments**: Inline diff comments and general reply comments must automatically line-wrap around 75 columns both when generating reply quotes (`MergePatchReviewQuote` / `WrapCommentText`) and when editing unquoted lines in the internal reply editor (`InternalEditor.js`), while preserving RFC `> ` quoted lines, fenced code blocks, `--- ` signatures, kernel/email trailer tag lines (`Fixes:`, `Link:`, `Closes:`, `*-by:`, `Cc:`, `Message-Id:`, `Change-Id:`, `BugLink:`, `Resolves:`, `base-commit:`, etc.), standalone/reference URL lines (`https://...`, `[1] https://...`, `- https://...`), and URL tokens across common schemes (`http://`, `https://`, `ftp://`, `git://`, `ssh://`, `mailto:`, etc.) without breaking or prematurely wrapping them.
- **Internal Editor Undo/Redo**: The internal email editor (`InternalEditor.js` + `EditorHistory` in `editorHistory.js`) must maintain an undo/redo stack supporting `Ctrl+Z`, `Ctrl+Y`, and `Ctrl+Shift+Z` across typing, line-wrapping, Tab insertion, and quick-tag insertion.
- **Unsaved Draft Close Guard**: `InternalEditor.js` tracks a dirty snapshot across `To`, `Cc`, `Subject`, `Body`, and `attachments`. When the user presses `Escape` or clicks Close (`✕`) with unsaved modifications, the editor must prompt the user with a 3-choice dialog (**Save & Close**, **Discard & Close**, **Cancel**) instead of silently closing, and pressing `Escape` inside an open recipient autocomplete dropdown must stop propagation so only the dropdown closes.

## 7. API Serialization & Nil-Slice Safety
- **No Null Arrays in JSON**: Slices representing collections (such as `paired_rows`, `unified_lines`, `hunks`, `attachments`, `comments`) must always be initialized to empty slices (`make(..., 0)` or `[]*T{}`) instead of `nil`. This guarantees they serialize as `[]` rather than `null`, preventing frontend iteration exceptions (`TypeError: ... is not iterable`).

## 8. MIME Attachment Security & Download Invariants
- **Filename Sanitization**: Always sanitize attachment filenames with `filepath.Base()` and strip directory traversal components (`../`), control characters, and quotes.
- **Secure Download Headers**: Attachment download endpoints must enforce `Content-Disposition: attachment; filename="..."; filename*=UTF-8''...` along with `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'`.

## 9. IMAP Sync & Checkpoint Progression Invariant
- **Contiguous Checkpoint Progression**: A folder's `last_synced_uid`
  checkpoint must only advance up to the highest contiguous server UID
  verified to be present in the local database. Never unconditionally
  advance the checkpoint to the maximum server UID if messages remain
  undownloaded or header fetches fail.
- **Strict Error Propagation**: Sync operations must never report
  completion (`status = "completed"`) or discard fetch errors when message
  summaries fail to download or return empty payloads. They must set
  `status = "error"`, record the error detail, and halt batch processing so
  subsequent automatic polling does not skip missing messages.

## 10. Active Configuration Presentation Invariant
- **No Raw Config File Echoing**: Never display configuration files
  directly as-is to the user or CLI. Raw files may contain obsolete,
  unparsed, or deprecated keys from previous versions.
- **Sectional Organization & Default Annotations**: Always present active
  configuration settings grouped by section. Any setting that has not been
  explicitly configured must be displayed with its key followed by its
  default value, preceded by a `#` comment symbol.

## 11. Inline Script Restrictions
- NEVER run inline scripts such as `python3 -c "..."`, `python -c "..."`, or arbitrary shell one-liners (`sh -c`, `bash -c`) for debugging, smoke testing, or verification.
- Do not request permission to execute embedded multiline code blocks via CLI flags.

## 12. Preferred Verification Procedures
Always verify changes using one of the following methods, in order of priority:

1. **Test Suite (Primary)**:
   - Run existing tests using the project's standard test runner:
     `pytest tests/path/to/test_file.py -k <test_name>`
   - If no relevant test exists, add a formal test case to the test suite.

2. **Temporary Script File (Secondary)**:
   - If an ad-hoc check is strictly necessary and cannot be integrated into a test suite, create a standalone temporary script file (e.g., `tests/tmp_verify.py` or `.tmp/scratch.py`).
   - Execute the file directly:
     `python3 tests/tmp_verify.py`
   - Clean up (delete) the temporary script as soon as the verification is complete.

## 13. Command Execution Rules
- Always execute commands against existing or newly created file paths.
- Ensure terminal commands are short, deterministic, and easily auditable in diffs.

## 14. Real-Time Notifications (SSE) & Database Watcher Invariants
- **No Broadcast on Read-Path Hydration**: Lazy fetching or hydration of message bodies from IMAP (e.g., during `GET /api/messages/{id}`) must never emit SSE broadcast events that trigger message list or folder reloads.
- **Prevent SQLite Watcher Self-Triggering & Pool Masking**: When monitoring `PRAGMA data_version;` to detect external out-of-process changes (such as `--mcp-stdio` or CLI mutations), `GetDataVersion()` must query a dedicated single-connection watcher handle (`watcherDB` with `SetMaxOpenConns(1)`), and all in-process daemon writes must call `d.MarkInProcessWrite()` (which also tracks `mainBaselineVersion` on `d.DB` to detect external writes that occurred immediately prior to an in-process write).
- **Actual-Change Publishing**: `mail.sync_completed` must only be published when new messages are added (`new_count > 0`) or messages are expunged (`removed_count > 0`). Never publish sync completion on no-op polling cycles.
- **Detailed `message.updated` Payloads**: Payloads for `message.updated` must include the specific modified fields (e.g. `message_id`, `message_db_id`, `folder`, `is_read`, `is_replied`, `tag`, and `flags`).

## 15. Frontend Granular State Patching & Deduplication Invariants
- **In-Place Row Patching on Updates**: The frontend SSE listener for `message.updated` must never trigger a full message list fetch (`fetchMessages()`). It must compare the payload against local state, treat identical state as a no-op, and patch row DOM elements (classes, read dots, tags) in-place.
- **Self-Echo Suppression**: Client-initiated REST calls that modify or inspect messages must register a temporary suppression window (via `suppressEventForMessage`) to prevent incoming self-echo SSE events from redundantly re-fetching message details or threads.
- **Detail Cache Invalidation on Comment/Review Events**: `messageDetailCache` must be invalidated by both numeric DB ID and string `message_id` whenever `review.comment_added`, `review.status_updated`, or `system.resync_required` arrives, and `fetchMessageComments()` must unwrap `{ message_id, comments }` to return the `comments` array so `activeNotes` and the `🗑️ Discard Drafts` button update immediately.
- **Single-Flight Fetch Guards**: High-frequency fetch functions (such as `fetchFolders()` and `fetchMessages()`) must use in-flight promise guards to prevent concurrent or overlapping executions from causing duplicate DOM renders.

## 16. Pre-Commit Go Code Review Subagent Invariant
- **Mandatory Subagent Review**: Whenever changes to Go code (`*.go`) are prepared for commit, launch a subagent using `invoke_subagent` (TypeName: `"self"`, Role: `"Go Code Reviewer"`) instructed to evaluate the uncommitted diff against the `go-review-agent` skill and Google Go Style Decisions.
- **Pre-Commit Remediation**: The parent agent must review the subagent's findings, remediate any non-idiomatic patterns, naming stuttering, unhandled/discarded errors, or test hygiene defects, and re-run `make test` and `make test-e2e` before committing.

## 17. Message Viewer, Diff Comments & Patchwork TODO Invariants

- **Markdown Rich-Text & Plain-Text Soft Wrapping**: Non-patch emails detected as Markdown (`isMarkdown`) render as sanitized rich HTML with a `📝 Rich Text` / `📄 Plain Text` toggle; plain-text mode must soft-wrap at the window edge (`white-space: pre-wrap; overflow-wrap: anywhere`) and collapse invisible email preheader padding characters (`\u2007`, `\u00a0`, `\u200b`, `\u034f`).
- **Configurable Patchwork TODO States & Query Safety**: Patchwork TODO synchronization (`patchwork.todo_states`) filters delegated patches using the configured state list (defaulting to `Under Review, New` when unspecified) and `archived=false`. Because Patchwork v1.4 rejects `order=-date` with HTTP 400 unless `project` or `series` is specified, `ListMyPatches` must use `order=-id` when `project` is omitted, and must propagate any HTTP/decode error rather than returning an empty slice so `SyncTodoFromPatchwork` never purges existing `TODO` messages on upstream errors.
- **Multi-Message Selection in Summary Pane**: `Ctrl+Click` (or `Meta+Click`) on any message row in `SummaryPane.js` enters multi-selection mode (`isMultiSelectMode`), displaying per-row selection checkboxes (`.summary-select-checkbox`) and the top-line action bar (`#summary-selection-bar`) with **🏷️ Tag them** (color tag picker and `0`–`9` shortcuts) and **🗑️ Trash them** (bulk delete) actions.
- **Startup Local Folder Sanitization**: Database initialization (`initDB` / `sanitizeLocalFolderMessages`) must clear any stray `imap_uid` values on local-only folders (`b4-imports`, `Drafts`, `TODO`, `Sent`, `AI-reviews`, `Trash`, `Outbox`), reconcile `is_read`, `is_replied`, and `flags` against the backing Maildir filename flags while preserving custom color tags, and clear stale missing `file_path` entries on IMAP folder messages so on-demand hydration can re-fetch them.

In the `Thread Hierarchy` message list (`vscode-extension/src/views/threadsProvider.ts`), each tagged `MessageTreeItem` resolves its custom color tag (`tag_key`, `tag_name`, `tag_color`, or `flags` against `/api/tags` and `DEFAULT_TAGS`), colors its `TreeItem` label via `MessageDecorationProvider` (`vscode.FileDecorationProvider` + contributed `undine.tag.*` `ThemeColor`s in `package.json`) and its `ThemeIcon`, and displays the tag badge and colored subject in `MessageHeaderViewProvider` (`undine.setMessageTag`).

## 18. Security Hardening Invariants
- **VS Code Workspace Isolation, Loopback Token Guard & Webview CSP**: `vscode-extension/package.json` must keep `undine.serverUrl` and `undine.authTokenPath` marked `"scope": "application"` and `"restricted": true`, and declare `capabilities.untrustedWorkspaces.supported = false`. `UndineRestClient` (`validateServerUrl`) must reject non-loopback or non-HTTP(S) URLs (and set `redirect: "error"`) before attaching `Authorization: Bearer`. `MessageHeaderViewProvider` must use a per-render cryptographic nonce in `script-src 'nonce-...'` (never `'unsafe-inline'`) and validate `http://` / `https://` schemes (`isSafeExternalHttpUrl`) before invoking `vscode.env.openExternal`.
- **Frontend XSS, URL, CSS & Tag-Color Sanitization**: All untrusted fields interpolated into HTML (`formatDate(m.date)`, Patchwork metadata, badges, attributes) must be HTML-escaped via `escapeHtml` / full `escapeAttr` (`& < > " '`). External hrefs (`pw.web_url`, `pw.url`, `c.target_url`, `sp.web_url`) must pass `sanitizeHttpUrl`, CSS class slugs must pass `sanitizeCssSlug`, tag colors must pass `sanitizeHexColor` (`#RGB` / `#RRGGBB`), and `markdown.js` `isSafeUrl` must reject protocol-relative `//...` URLs. `InternalEditor.js` must remove orphaned `localStorage` composer drafts when `window.open` is blocked.
- **Strict Exact-Origin CSRF & Host Defense**: `SecurityManager.ValidateOrigin` must enforce exact `scheme://host:port` (plus default port 80 normalization) matching against `AllowedOrigins` with no hostname-only port-ignoring fallback; production `AllowedHosts` must not include `"test"` or `"testserver"`. Cookie-authenticated `POST` requests to `/api/*` must require `Content-Type: application/json` (`415 Unsupported Media Type` otherwise) to block browser simple-request CSRF.
- **Security Response Headers & Opt-In External Fonts**: `SecurityHeadersMiddleware` must attach `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, and `Content-Security-Policy` to all responses (`default-src 'none'; frame-ancestors 'none'` on non-UI routes). External Google Fonts loading is disabled by default (`[general] allow_external_fonts = false`); only when explicitly enabled are Google Fonts `<link>` tags injected into `/` and `/login` and permitted in UI CSP.
- **Token File Atomicity, `?token=` Scope & CLI Secret Redaction**: `SecurityManager.initToken` and `RenewToken` must reject symlinks/non-regular files via `os.Lstat`, atomically write tokens via a `0600` temp file + `Sync` + `os.Rename`, and rotate pre-existing token files whose group/world permission bits are set. `ExtractToken` must only accept `Authorization: Bearer` and the session cookie (never `?token=` on `/api/*`, keeping `?token=` strictly for `/` login bootstrap). `FormatActiveConfig` (`undined config show`) must redact non-empty `imap.password`, `smtp.password`, and `patchwork.token` values as `"[REDACTED]"`.
- **Transport, MCP Attachment & Temp-File Safety**: `patchwork.Client.HTTPClient` must enforce a same-origin, no-scheme-downgrade `CheckRedirect` policy and bound error/mbox reads via `io.LimitReader`. `smtp.Client` must abort with an explicit error when `use_starttls = true` and the server does not advertise `STARTTLS`. `parseMCPAttachments` (`isBlockedMCPAttachmentPath`) must canonicalize symlinks and reject sensitive UndineD (`auth_token`, active `config.toml`, `DataDir`) and user/system credential paths (`~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.kube`, `~/.netrc`, `~/.git-credentials`, `/proc/self/environ`). External editor draft files (`internal/bridge/editor.go`) must be created atomically with `os.CreateTemp` (`0600`) and cleaned up on launch failure.
