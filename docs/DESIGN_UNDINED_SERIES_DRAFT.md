# Design Specification: UndineD MCP Draft-Only Tools & Human-Controlled Patch Series Send UI (`DESIGN_UNDINED_SERIES_DRAFT.md`)

## 1. Overview & Security Boundary

This companion specification defines the additions required in **UndineD** (`mhiramat/undined`) to support **kdevkit Phase 4** (patch series authoring, review import, and Pull Request skill integration) while enforcing a strict **Human-in-the-Loop Accountability Boundary**.

### Core Safety Invariant: Zero SMTP Transmission from MCP
* **MCP tools in UndineD MUST NEVER send email over SMTP.**
* Automated tools (`kdevkit` VSCode extension, Pull Request skills, or AI review agents) may only **read archives**, **export mbox files**, **update Patchwork metadata**, and **stage plain-text drafts** into UndineD's Maildir `Drafts` folder.
* **Final review, optional editing, and SMTP transmission are performed exclusively by a human operator inside the UndineD Web UI.**

### Summary of Required Additions in UndineD
1. **Three new MCP tools** (`internal/mcp/`):
   * `create_mail_draft` — Stage a standalone plain-text email draft (used by the existing Pull Request skill and general drafts).
   * `stage_patch_series` — Stage a threaded multi-email patch series (optional cover letter `0/N` + patches `1/N..N/N`) as a grouped draft queue.
   * `export_thread_mbox` — Export a local thread/series from Maildir as a `git am`-ready mbox file for `kdevkit` review/maintainer import.
2. **Patch Series Draft Queue & Controlled Batch Send** (`internal/series/`, `internal/api/`, `frontend/`):
   * Group staged series drafts in the UndineD Web UI `Drafts` view so the human can inspect/edit the cover letter, individual patches, and shared `To`/`Cc` headers.
   * Provide a human-confirmed, rate-controlled, pause/cancel/resume sequential SMTP sender (`0/N` → `1/N` → ... → `N/N`) that guarantees zero duplicate transmissions on partial failure.

## 2. New MCP Tool Specifications (`internal/mcp/`)

All new MCP tools reuse UndineD's existing strict plain-text MIME/RFC 5322 builder (`Content-Type: text/plain; charset=utf-8`, `Content-Transfer-Encoding: 8bit`, raw `\t` retention, zero automatic line wrapping, `X-Mailer: UndineD ...`) and write structured audit logs to `~/.cache/undined/undined.log`.

### 2.1 `create_mail_draft`
Creates a standalone plain-text email draft in Maildir `Drafts` (unlike the existing `create_review_draft`, this tool does **not** require a `target_message_id` reply parent, making it suitable for Linus Pull Requests and new threads).

#### Parameters
| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `to` | `string[]` | Yes | Recipient email addresses (`Name <addr>` or `addr`) |
| `cc` | `string[]` | No | Carbon-copy recipients |
| `subject` | `string` | Yes | Email subject (e.g., `[GIT PULL] probes: Fixes for v6.14-rc3`) |
| `body` | `string` | Yes | Strict plain-text UTF-8 body (tabs and newlines preserved verbatim) |
| `in_reply_to` | `string` | No | Optional parent `Message-ID` |
| `references` | `string[]` | No | Optional `References` chain |
| `extra_headers` | `Record<string, string>` | No | Optional allowlisted headers (e.g., `X-Kdevkit-Branch`) |
| `tags` | `string[]` | No | Optional UndineD color/custom tags to attach (e.g., `["PR-Draft"]`) |

#### Response
```json
{
  "draft_id": "msg_01J...",
  "message_id": "<20261123112000.98412-1-mhiramat@kernel.org>",
  "maildir_path": ".../Drafts/cur/...",
  "web_url": "http://127.0.0.1:8080/#drafts/msg_01J..."
}
```

### 2.2 `stage_patch_series`
Stages a complete patch series generated by `kdevkit` into Maildir `Drafts` and registers it in UndineD's series draft store so the Web UI presents it as a unified reviewable/sendable queue.

#### Parameters
| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `series_key` | `string` | Yes | Stable logical key (e.g., `topic/fprobe-cleanup:v2`) for idempotency / replacing an existing unsent draft |
| `branch` | `string` | No | Source Git branch name (displayed as badge in Web UI) |
| `version` | `integer` | No | Series version number (`1`, `2`, ...) |
| `to` | `string[]` | Yes | Shared `To` recipients for the series |
| `cc` | `string[]` | No | Shared `Cc` recipients for the series |
| `in_reply_to` | `string` | No | Optional external thread `Message-ID` (e.g., replying to a bug report or previous version) |
| `base_commit` | `string` | No | Upstream base commit SHA (informational metadata) |
| `replace_existing` | `boolean` | No | Default `false`. If `true` and an unsent draft queue with `series_key` exists, replaces it cleanly (refuses if any message in the queue was already sent) |
| `messages` | `SeriesMessage[]` | Yes | Ordered array (`0/N` cover letter first if present, followed by `1/N`..`N/N`) |

Each `SeriesMessage` contains:
* `index` (`integer`): `0` for cover letter, `1..N` for patches.
* `is_cover_letter` (`boolean`): `true` only for `0/N`.
* `subject` (`string`): Exact LKML subject line (e.g., `[PATCH v2 0/3] ...`).
* `body` (`string`): Exact plain-text body (including commit message, `---`, diffstat, and unified diff for patches; **must not be modified or wrapped**).
* `commit_sha` (`string`, optional): Originating Git commit SHA for traceability.
* `extra_to` / `extra_cc` (`string[]`, optional): Per-patch additional recipients (e.g., file-specific maintainers from `get_maintainer.pl`).

#### Threading & RFC 5322 Generation Rules
1. Generate a monotonic, deterministic `Message-ID` root `<YYYYMMDDHHMMSS.<pid/rand>-<index+1>-<from_email>>` (matching `git send-email` convention).
2. **Thread Linkage:**
   * Message `0` (cover letter, or patch `1` if single/coverless): sets `In-Reply-To` / `References` only if top-level `in_reply_to` was supplied.
   * All subsequent patches (`1..N`): automatically set `In-Reply-To: <root_message_id>` and `References: [<optional_parent>, <root_message_id>]` so every LKML client and lore.kernel.org groups the series cleanly.
3. Inject internal tracking headers (stripped automatically before SMTP transmit):
   * `X-Undine-Series-ID: <series_id>`
   * `X-Undine-Series-Index: <index>`
   * `X-Undine-Series-Total: <total>`
4. Persist every message as a standard RFC 5322 file in Maildir `Drafts` and emit an SSE event (`series_draft_updated`) so an open UndineD Web UI tab updates immediately.

#### Response
```json
{
  "series_id": "ser_01J...",
  "series_key": "topic/fprobe-cleanup:v2",
  "message_count": 4,
  "root_message_id": "<20261123112500.41022-1-mhiramat@kernel.org>",
  "items": [
    { "index": 0, "draft_id": "msg_01J...0", "message_id": "<...-1-...>", "status": "draft" },
    { "index": 1, "draft_id": "msg_01J...1", "message_id": "<...-2-...>", "status": "draft" }
  ],
  "web_url": "http://127.0.0.1:8080/#series/ser_01J..."
}
```

### 2.3 `export_thread_mbox`
Allows `kdevkit` (and review skills) to pull a `git am`-ready mbox directly from UndineD's Maildir/SQLite store without duplicate network fetches when the thread was already synced via IMAP or `import_patch_series_b4`.

#### Parameters
| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `message_id` | `string` | Yes | Any Message-ID in the target patch or series thread |
| `output_path` | `string` | No | Optional destination path (restricted to temp/allowed dirs); if omitted, writes to UndineD cache temp file and returns path |
| `patches_only` | `boolean` | No | Default `true`. Filters to patch messages ordered by `[PATCH x/N]` index and attaches collected thread trailers when available |

#### Response
```json
{
  "mbox_path": "/tmp/undined-export-xxxx.mbx",
  "patch_count": 3,
  "base_commit": "a1b2c3d4e5f6...",
  "root_message_id": "<...>"
}
```

## 3. Storage Schema & Backend Series Manager (`internal/series/`)

### 3.1 SQLite Schema Extension (`undine.db`)
Add two tables while keeping the canonical RFC 5322 email files inside Maildir `Drafts` (preserving drop-in Maildir compatibility):

```sql
CREATE TABLE IF NOT EXISTS patch_series_drafts (
    series_id       TEXT PRIMARY KEY,
    series_key      TEXT NOT NULL,
    branch          TEXT DEFAULT '',
    version         INTEGER DEFAULT 1,
    base_commit     TEXT DEFAULT '',
    to_addrs        TEXT NOT NULL,     -- JSON array
    cc_addrs        TEXT NOT NULL,     -- JSON array
    in_reply_to     TEXT DEFAULT '',
    status          TEXT NOT NULL,     -- 'draft' | 'sending' | 'paused' | 'failed' | 'sent'
    send_delay_sec  INTEGER DEFAULT 2,
    created_at      DATETIME NOT NULL,
    updated_at      DATETIME NOT NULL
);

CREATE TABLE IF NOT EXISTS patch_series_items (
    series_id       TEXT NOT NULL REFERENCES patch_series_drafts(series_id) ON DELETE CASCADE,
    seq_index       INTEGER NOT NULL,  -- 0 = cover letter, 1..N = patches
    is_cover_letter INTEGER NOT NULL DEFAULT 0,
    draft_msg_id    TEXT NOT NULL,     -- Internal Maildir/SQLite message ID
    rfc_message_id  TEXT NOT NULL,
    subject         TEXT NOT NULL,
    commit_sha      TEXT DEFAULT '',
    extra_to        TEXT DEFAULT '[]', -- JSON array
    extra_cc        TEXT DEFAULT '[]', -- JSON array
    status          TEXT NOT NULL,     -- 'draft' | 'sending' | 'sent' | 'failed'
    error_message   TEXT DEFAULT '',
    sent_at         DATETIME,
    PRIMARY KEY (series_id, seq_index)
);
```

### 3.2 REST API & SSE Endpoints (`internal/api/`)
All state-mutating endpoints require UndineD's existing authentication token and are strictly scoped to the Web UI (never exposed over MCP):

| Method & Endpoint | Purpose |
| :--- | :--- |
| `GET /api/series` | List active and recently sent patch series draft queues |
| `GET /api/series/{id}` | Retrieve full series metadata, item statuses, and validation warnings |
| `PUT /api/series/{id}/headers` | Bulk-update shared `To`, `Cc`, `In-Reply-To`, or `send_delay_sec` across all unsent items in Maildir `Drafts` |
| `PUT /api/series/{id}/items/{index}` | Save human edits to a specific cover letter or patch (updates Maildir file verbatim; validates diff integrity for non-cover patches) |
| `POST /api/series/{id}/test-send-self` | Optional dry-run: sends the series only to `smtp.from_email` (with `[TEST]` tag or preserved headers, never marking items as `sent` to LKML) |
| `POST /api/series/{id}/send` | Start or **resume** sequential human-initiated SMTP transmission for all remaining `draft`/`failed` items |
| `POST /api/series/{id}/cancel` | Gracefully halt after the currently transmitting email finishes (`status = 'paused'`) |
| `DELETE /api/series/{id}` | Discard an unsent series queue and delete its Maildir `Drafts` files |

### 3.3 Controlled Sequential SMTP Sender (`internal/series/sender.go`)
1. **Single-Flight Lock:** Only one send goroutine may run per `series_id`.
2. **Pre-Send Header Normalization:**
   * Strip internal `X-Undine-Series-*` headers prior to SMTP `DATA`.
   * Re-verify `In-Reply-To` and `References` consistency in case the user edited or deleted the cover letter.
   * Enforce strict 8-bit UTF-8 plain text with zero line-wrapping and raw `\t` tab preservation.
3. **Sequential Delivery with Pacing:**
   * Iterate strictly in ascending `seq_index` order (`0` → `1` → ... → `N`), skipping any item where `status == 'sent'`.
   * Transmit one message via UndineD's existing SMTP client.
   * Immediately upon SMTP `250 OK`:
     * Move the Maildir file from `Drafts` to `Sent` (syncing to IMAP `Sent` per existing UndineD behavior).
     * Mark item `status = 'sent'`, `sent_at = NOW()` inside a SQLite transaction.
     * Broadcast SSE event `series_send_progress { series_id, seq_index, status: "sent", sent_count, total_count }`.
   * Wait `send_delay_sec` (default `2s`, interruptible by context cancel) before sending the next patch so mail relays and lore.kernel.org preserve chronological arrival order and avoid burst throttling.
4. **Failure & Resume Guarantees:**
   * On any SMTP error at index `k`: mark item `k` as `failed` with `error_message`, set series `status = 'failed'`, emit SSE error event, and stop immediately.
   * Because items `0..k-1` are already persisted as `sent`, clicking **Resume Send** after fixing the issue (e.g., temporary network drop or typo in an address) resumes cleanly at index `k` with **zero risk of double-sending `0..k-1`**.

## 4. UndineD Web UI Design (`frontend/`)

### 4.1 Drafts Folder Grouping
* In the 3-pane Sylpheed-style message list when viewing `Drafts`:
  * Messages belonging to a `patch_series_drafts` record are collapsed into a single **Series Queue Row** (e.g., `📦 [Series v2 · 4 msgs] [PATCH v2 0/3] fprobe: cleanup...` with branch badge `topic/fprobe-cleanup` and status pill `Draft` / `Paused 2/4` / `Failed`).
  * Standalone drafts (such as a Linus Pull Request created via `create_mail_draft`) remain standard clickable draft rows opening directly in UndineD's existing strict plain-text composer.

### 4.2 Patch Series Review & Send Workspace (`#series/{series_id}`)
Clicking a Series Queue Row opens a dedicated review workspace inside the main viewer pane:

1. **Top Series Header Bar:**
   * Editable shared **To** and **Cc** fields (changes apply to all unsent items in the queue).
   * Optional **In-Reply-To** field and **Inter-patch delay** selector (`1s` / `2s` / `5s`).
   * Primary action buttons:
     * **Send Test to Self** (`from_email`)
     * **Send Series (N emails)...** (or **Resume Remaining (K/N)...** when paused/failed)
     * **Discard Series**
2. **Left/Top Patch List (`0/N` .. `N/N`):**
   * Shows index, subject, per-item status badge (`Draft`, `Edited`, `Sent ✓`, `Failed ✗`), and optional per-patch extra recipients.
3. **Message Inspector & Strict Plain-Text Editor:**
   * Toggle between **Rendered Diff View** (reusing UndineD's existing side-by-side / tab-preserving patch renderer) and **Edit Plain Text** (reusing UndineD's built-in tab-preserving composer + `Ctrl+E` external `$EDITOR` launch).
   * **Diff Integrity Guard:** If the human edits a non-cover-letter patch email (`index >= 1`), run a lightweight sanity check on save to warn (non-blocking) if unified diff hunk line counts (`@@ -a,b +c,d @@`) appear broken or tabs were converted to spaces.
4. **Human Confirmation Modal (Before Any SMTP Transmission):**
   * Displays an unambiguous summary before transmitting:
     * SMTP account (`from_email` via `smtp.host`)
     * Total message count and ordered subject list
     * Full deduplicated `To` and `Cc` recipient list
     * Any warnings (e.g., missing `Signed-off-by:`, edited diff hunk warning)
   * Requires explicit click on **Confirm & Send Series** (never auto-triggered).
   * Transitions into a live **Send Progress Drawer** driven by SSE with a **Pause / Cancel** button.

## 5. Implementation & Test Plan (`undined`)

### Implementation Order
1. **Step 1 — Storage & `create_mail_draft` / `export_thread_mbox` MCP Tools:**
   * Add SQLite migration for `patch_series_drafts` / `patch_series_items`.
   * Implement `create_mail_draft` (immediately usable by the developer's existing Pull Request skill) and `export_thread_mbox`.
2. **Step 2 — `stage_patch_series` MCP Tool & Series REST/Sender Backend:**
   * Implement RFC 5322 threading builder, Maildir `Drafts` persistence, `internal/series/sender.go` sequential SMTP worker, REST handlers, and SSE progress events.
3. **Step 3 — Web UI Series Review & Send Workspace:**
   * Group series items in `Drafts`, build the Series Review & Edit view, confirmation modal, and live progress/pause/resume controls.

### Verification & Test Plan (`make test`)
* **MCP Draft-Only Enforcement Tests (`internal/mcp/series_test.go`):**
  * Verify `create_mail_draft` and `stage_patch_series` create exact 8-bit UTF-8 Maildir files with `\t` tabs preserved verbatim and proper `Message-ID` / `In-Reply-To` / `References` threading.
  * Assert zero SMTP transport calls occur during any MCP tool invocation.
  * Verify `replace_existing: true` replaces an unsent draft cleanly, and returns an error if any message in the series is already `sent`.
* **Sequential Sender & Resume Tests (`internal/series/sender_test.go`):**
  * Using a mock SMTP server, verify strict `0/N -> 1/N -> ... -> N/N` ordering, header stripping of `X-Undine-Series-*`, and pacing delay.
  * Inject an SMTP failure on patch `2/4`: verify `0/4` and `1/4` are marked `sent` and moved to `Sent`, `2/4` is marked `failed`, `3/4` remains `draft`.
  * Invoke `Send` again (resume) with mock SMTP healthy: verify only `2/4` and `3/4` are transmitted (total sends = 4, zero duplicates).
* **Frontend & E2E Tests:**
  * Verify Drafts grouping, bulk `To`/`Cc` update propagation, diff-integrity warning on corrupted hunk edit, and Pause/Resume UI state transitions via SSE.
